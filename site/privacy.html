Privacy Policy

This policy describes how SOKEN LTD handles data in connection with the Soken Contract Review connector ("the Service").

1. Data controller

SOKEN LTD, a company registered in England and Wales under number 15253906, with its registered office at 86-90 Paul Street, London, EC2A 4NE.

Privacy contact: hello@soken.dev

2. Data we process

2.1 Review job data

When you use the Service, the following data is sent to the server as MCP tool arguments from your language-model session:

  • The review target: a deployed contract address and chain, a repository URL and commit, source files pasted in the conversation, or an uploaded archive of private code.
  • The requester role you declare (owner, authorized, or third-party public code).
  • The findings, challenge answers, dismissal reasons, and report sections your language-model session writes and sends as tool arguments.
  • Project context documents you supply: URLs to whitepapers, websites, apps, docs, terms, or privacy pages, or inline text. When you provide a URL, the server fetches it in a sandbox (HTTPS only, up to 10 MiB per document, at most 12 per job). For website and app URLs, up to five same-origin script bundles named by the HTML are also fetched and scanned for contract addresses and chain identifiers.
  • Job metadata (timestamps, states, build and analyzer outputs).

2.2 Network data

For direct connections, the server receives the client IP address. It is stored only as a keyed HMAC hash, never in raw form. No identifier is derived from it; it is used for product metrics only.

For requests relayed by Anthropic's infrastructure (claude.ai), the server sees the relay IP range, not your personal IP address. The limit is then counted per reviewed target.

2.3 Claim page

If you use the claim page to prove code ownership, we process the address, the cryptographic signature or memo transaction you submit, and the commit (for repository inputs). Only a sha256 hash of the signature is stored.

2.4 Publication consent

If you call review_publish with a consent object, the party name, authorising person name, consent statement, and your timestamp are logged. This consent record survives deletion of the review job.

2.5 What we do not read

The Service does not read your chat history, memory, conversation summaries, or other files. Source code is received only as MCP tool arguments that your session sends on your request.

3. Purposes and lawful basis

We process this data for the following purposes, on the basis of legitimate interests:

  • Delivering the review report you requested.
  • Product metrics (without chat data or raw IP addresses).
  • Responding to support and takedown emails.
  • Publishing the report if you give explicit consent through review_publish.

We do not use submitted code or findings for marketing, model training, or benchmarking.

4. Data recipients

The server makes outbound requests to the following third-party services to fetch source code, verify deployments, and read on-chain state. Only data necessary for the review (addresses, bytecode hashes, chain identifiers) is sent; your findings and report text are never sent to these services.

4.2 IPFS gateways

For EVM contracts whose Solidity metadata references IPFS content identifiers, the server fetches source from IPFS gateways: Filebase, Lighthouse, Pinata, and 4everland.

4.3 Blockchain RPC providers

The server reads on-chain state (bytecode, storage, account data) from RPC providers. Only read-method calls are made; no transaction is ever signed or sent. Providers include public and commercial RPC endpoints for each supported chain (EVM, HyperEVM, TRON via TronGrid, Solana, TON via toncenter and verifier.ton.org, Aptos).

4.4 Git hosts

For repository inputs, the server clones from GitHub, GitLab, or Codeberg using HTTPS. Only the repository URL, commit, and ref you provide are used.

4.5 Context document URLs

When you supply URLs for project documents (whitepaper, website, app, docs, terms, privacy), the server fetches each URL in a sandboxed container. The user-agent string is soken-doc-fetch/1 (+https://soken.dev). Only HTTPS URLs are accepted.

4.6 Publication

If you consent to publication, the report PDF is pushed to the public GitHub repository Soken-LTD/smart-contract-audits and listed on soken.dev/audits.

4.7 Infrastructure

The Service is hosted on DigitalOcean infrastructure in the London (LON1) region. Backups are stored in the Amsterdam (AMS3) region. The database is DigitalOcean Managed PostgreSQL. Object storage uses DigitalOcean Spaces (London, with a backup bucket in Amsterdam).

5. International transfers

All primary processing occurs in the London (LON1) region. Encrypted backup copies are stored in the Amsterdam (AMS3) region. When the server contacts third-party services listed above, your contract address and chain are sent to those services, which may process data outside the UK.

7. Your rights

Under the UK General Data Protection Regulation (UK GDPR), you have the right to:

  • Access the personal data we hold about you.
  • Request correction of inaccurate data.
  • Request deletion of your data.
  • Object to processing based on legitimate interests.
  • Request restriction of processing.
  • Data portability.

How to delete your data

You can delete a review job and all associated data (source, findings, report, PDF) at any time using one of the following methods:

  • Call the review_delete_job tool with the job id and confirm: "delete".
  • Use the manage page at the link provided in the report result.
  • Email hello@soken.dev with the report id or job id.

Deletion removes source code, findings, the hosted report, and the PDF. Tombstone records (containing only hashes and the deletion reason) are kept for the periods listed in the retention table. Publication consent logs survive job deletion as they serve as the legal record of consent to permanent publication.

Published reports (on GitHub and soken.dev/audits) are not removed by deleting a job. To request removal of a published report, see the takedown page.

Complaints

If you are not satisfied with how we handle your data, you have the right to lodge a complaint with the Information Commissioner's Office (ICO) at ico.org.uk.
