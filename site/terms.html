4. Third-party code and publication

When you review code you do not own, the report is issued under a restricted profile ("public_review"). Under this profile, the detailed exploit narrative of any High or Critical finding is withheld, report links expire after one hour, and the cover carries a banner stating that code ownership is not proven. This restriction is lifted only when the code owner proves control through the claim page on soken.dev.

If you call review_publish with a consent object, the report PDF is published automatically, without manual review by SOKEN LTD, to the public GitHub repository Soken-LTD/smart-contract-audits and to soken.dev/audits. Published reports are labelled "Automated by SOKEN MCP". One published report per reviewed target: a later published review of the same target (same contract address on the same chain, or same repository) replaces the earlier file rather than adding a second one.

The consent record (party, name, statement, timestamp) is kept as a legal record even after the review job is deleted. Published copies are permanent until a takedown request is honoured. See the takedown page for the removal process.

Ownership of the reviewed code is not verified by the Service. You are responsible for ensuring you have the right to publish a review of any code you submit for publication. Before publishing any finding about code operated by others, report it privately to the code owner and allow time for a fix.
